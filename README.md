# noctalia-screen-owner

Свой источник плагинов noctalia. Пока в нём один плагин — **Screen Owner**,
панель к демону [`screen-owner`](https://claude.ai/artifact/YJksCBvdkRUSHVTjgdyvEv):
каждый комплект клавиатура+мышь владеет своим монитором.

## Как это разделено

Демон `~/.local/bin/screen-owner` делает всю настоящую работу: держит
`EVIOCGRAB` на клавиатурах, отдаёт их Hyprland через копии на uinput, слушает
сокет композитора. Из Luau такого не сделать, поэтому плагин — только лицо.

Разговаривают они через CLI демона:

| Команда | Что делает |
|---|---|
| `screen-owner devices` | JSON: все клавиатуры и мыши, их тип, привязка и есть ли права |
| `screen-owner monitors` | JSON: подключённые мониторы и их центры |
| `screen-owner assign <железка> <монитор\|none>` | правит `~/.config/screen-owner/config.json` |
| `screen-owner grab <нода> <on\|off>` | перехватывать эту клавиатуру или нет |
| `screen-owner udev-rule [--install]` | правило доступа под выбранные железки |

Конфиг демон перечитывает сам, в течение трёх секунд — перезапускать не надо.

Имена железок берутся из sysfs, а он читается без всяких прав. Поэтому панель
показывает и те устройства, к которым доступа ещё нет, и честно предлагает его
выдать, вместо того чтобы молча их прятать.

## Что нужно поставить

`python-evdev` — на нём написан демон. `polkit` — чтобы панель могла записать
правило udev под `pkexec` (команда меняется в настройках плагина).

`input-remapper` **не нужен**: демон открывает только железки из своего белого
списка, геймпад и виртуальные устройства ремаппера ему не видны. Пресет `couch`
и этот плагин друг о друге не знают и не мешают друг другу.

## Установка

```sh
noctalia msg plugins source add brick git https://github.com/AnatoliyShevchenko/noctalia-screen-owner
noctalia msg plugins enable brick/screen-owner
```

Дальше открой панель и нажми **Установить**. Она сама:

1. поставит `python-evdev` через `pacman` под `pkexec` (пароль спросит polkit);
2. положит демон из каталога плагина в `~/.local/bin/screen-owner`;
3. запустит его.

Демон едет внутри `screen-owner/` именно поэтому: noctalia материализует из
источника только каталог плагина, всё остальное в репозитории до чужой машины
не доезжает.

Права на устройства выдаёт кнопка **Выдать доступ** — она собирает правило
udev из VID:PID тех железок, что ты назначил, и ставит его тем же `pkexec`.

Автозапуск панель **не** прописывает: `hyprland.lua` — твоя территория. Она
показывает строку и кладёт её в буфер:

```lua
hl.exec_cmd(bin("screen-owner"))
```

### Если правишь код

Тогда не копия, а симлинк, чтобы `git pull` обновлял демон заодно:

```sh
git clone https://github.com/AnatoliyShevchenko/noctalia-screen-owner ~/Projects/noctalia-screen-owner
ln -s ~/Projects/noctalia-screen-owner/screen-owner/screen-owner.py ~/.local/bin/screen-owner
```

Панель существующий файл не трогает — пишет только когда его нет.

Обновления: `noctalia msg plugins update brick`.

## Панель

Строка на железку: имя, тип, монитор. Клик — следующий монитор по кругу,
последним идёт «не привязан». Правый клик — выбор из списка. С двумя мониторами
клика достаточно, меню нужно редко.

Если у назначенной железки нет прав, внизу появляется кнопка **Выдать доступ**:
она пишет `/etc/udev/rules.d/70-screen-owner.rules` под `pkexec` (команда
меняется в настройках плагина) и перезагружает udev.

## Чего тут намеренно нет

**Поддержки других композиторов.** Переключение написано на диспетчерах
Hyprland (`hl.dsp.focus`, `hl.dsp.cursor.move`), а noctalia живёт ещё на Niri,
sway и labwc. Плагин сделан для себя и честно объявлен Hyprland-only.

**Поддержки не-USB устройств.** Железки опознаются по `/dev/input/by-id/`,
а туда попадает только USB — на десктопе это 6 нод из 25. Встроенная
клавиатура ноутбука (PS/2) и тачпад (i2c) живут лишь в `by-path`, поэтому
выбрать их в панели пока нельзя. Чинится смешанной идентификацией и отдельной
формой udev-правила: у не-USB устройств нет `ATTRS{idVendor}`.

## Замечания по устройству

- Правило udev обязано называться `70-…`: `73-seat-late.rules` проверяет
  `TAG=="uaccess"` раньше, и файл с большим номером опоздает.
- Комментарии в правилах — только отдельной строкой, инлайновых udev не
  понимает и молча выбрасывает всю строку.
- `plugin_api = 28`: 24 нужен для запуска процессов вектором аргументов,
  28 — для контекстного меню на строке устройства.
- Тип железки определяется по наличию буквенных клавиш, а не по `EV_KEY`:
  кнопки есть и у мыши. Железки, у которых есть и буквы, и указатель,
  помечаются как `combo` — это не ошибка определения, а правда про них.
